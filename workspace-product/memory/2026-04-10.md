### 关键经验（踩坑总结）

#### 1. 图片 URL 必须用微信素材库地址
- **不能**用 img402.dev 等外部图床链接，微信会过滤
- 先用 `material/add_material` 上传图片，获取 `mmbiz.qpic.cn` 地址
- 在研读报告 markdown 中手动插入图片 HTML

#### 2. 正文中的图片必须手动插入
- PDF 提取只能得到图片文件，**不会**自动插入正文
- 需要根据论文内容，在适当位置（章节标题后、表格前后）手动插入：
  ```html
  <p align="center"><img src="mmbiz_url" width="600"/></p>
  <p>图1：图片说明（来源：原论文 Figure X）</p>
  ```
- caption 单独一行作为普通段落输出

#### 3. LaTeX 公式必须转文字描述
- 微信公众号不支持 LaTeX
- 将 `$$...$$` 公式块替换为 1-2 句话文字描述

#### 4. WeChat 不支持空行，用 CSS margin-top 替代
- WeChat 编辑器会忽略纯空行（`''`）和裸 `<br/>` 标签
- **正确方案**：所有段落统一加 `margin-top:16px`（间距一致，效果最好）

#### 5. margin-top 加在哪些位置
- **全部段落**：`margin-top:16px`（统一间距）
- 顶级章节标题（H2 全部、H3 中匹配 `^\d+\.\s+` 的）：再加 `margin-top:20px`（额外间距）
- 子章节（H4 如 `#### 1.1`）：不加额外 margin
- 顶级章节紧跟 `<hr/>` 后：加 `margin-top:20px`（用 `prev_was_hr` 标志）

#### 6. HTML 标签不能转义
- `<p align="center"><img src="...">` 不能写成 `&lt;p`
- HTML 标签行直接 append 到结果列表，**不经过 escape 函数**

#### 7. 表格单元格双重加粗问题
- 单元格内容已有 `**粗体**` 标记，先 escape 再 inline_format 会导致重复
- **解决**：先 `strip_md_format`（去掉原始 `**`）再处理

#### 8. text-align CSS 问题（重要教训）
- 最初尝试 `text-align:left`，WeChat 反而显示异常
- **教训**：直接用裸 `<p>` 标签，WeChat 默认就是左对齐，**不要加多余 CSS**

#### 9. 研读报告 markdown 中不要写 HTML 标签
- PDF 文本提取可能带入 HTML 片段，或手动写了 `<p>` 标签
- **解决**：统一用纯 Markdown 格式书写，转换脚本处理所有 HTML 生成

### Markdown → HTML 转换核心伪代码

```python
def convert_md_to_html(md):
    lines = md.split('\n')
    result = []
    table_rows = []
    first_block = True
    prev_was_hr = False

    for line in lines:
        stripped = line.strip()

        if stripped.startswith('|'):          # 表格行
            table_rows.append(stripped)
            continue

        if table_rows:
            result.extend(process_table(table_rows))
            table_rows = []
            first_block = False

        if stripped == '':
            continue

        if re.match(r'^-{3,}$', stripped):   # 分隔线
            result.append('<hr/>')
            result.append('')
            prev_was_hr = True
            first_block = False
            continue

        hm = re.match(r'^(#{1,4})\s+(.+)$', stripped)
        if hm:
            level = len(hm.group(1))
            text = hm.group(2)
            if level == 1:
                continue                              # H1 跳过
            elif level == 2:
                if text in ['核心信息', 'Part A:', 'Part B:']:
                    continue                        # 元标题跳过
                result.append(f'<p style="margin-top:20px"><strong>{text}</strong></p>')
            else:                                      # H3/H4
                is_top = bool(re.match(r'^\d+\.\s+', text))
                needs_margin = (not first_block and is_top) or (prev_was_hr and is_top)
                tag = f'<p style="margin-top:20px"><strong>{text}</strong></p>' if needs_margin else f'<p><strong>{text}</strong></p>'
                result.append(tag)
            prev_was_hr = False
            first_block = False
            continue

        if is_html_line(stripped):                 # 图片等 HTML 行
            result.append(stripped)                  # 直接保留，不 escape
            prev_was_hr = False
            continue

        if stripped.startswith('- '):             # 列表项
            text = inline_format(escape(strip_md(stripped[2:])))
            result.append(f'<p style="margin-top:16px">{text}</p>')
            prev_was_hr = False
            first_block = False
            continue

        # 普通段落：全部加 margin-top:16px
        text = inline_format(escape(strip_md(stripped)))
        result.append(f'<p style="margin-top:16px">{text}</p>')
        prev_was_hr = False
        first_block = False

    return '\n'.join(result)
```

## ★★★ 列表嵌套问题根因与解决方案（2026-04-10 最终总结）

**问题现象**：微信公众平台上传后，列表项显示为多级列表（黑点 + 空心圆点嵌套），每两项之间出现孤立圆点。

2. WeChat 编辑器自动把 "职位：内容" 模式的段落识别为列表并加实心圆点

- 团队角色列表 → 用**纯文本段落**，用**分号 `；` 分隔**，角色名用 **`<strong>` 加粗**
- 示例：
  ```

  ```
- Markdown 转换脚本中，所有 "- xxx" 列表项统一转成 `<p>text</p>`，不用 `<ul><li>`
- **去掉所有空行**：内容连续排列，防止 WeChat 把多行识别为嵌套列表

**已验证的转换规则**：
1. 列表项 "- xxx" → `<p style="margin-top:16px">text</p>`（不用 `<ul>`）
